## Root Cause Analysis

### Issue 1: PE Session Length Calculation Bug

**Root Cause:** PE subjects have `duration_hours = 2` in database, causing:
- `calculateSessionConfig` to return 120-minute sessions
- `calculateOptimalSessionLength` to use 120 minutes as divisor
- This creates 2-hour sessions instead of 90-minute sessions

**Why This Happens:**
- The function `calculateOptimalSessionLength` (line 539-562) finds divisors of totalMinutes
- For PE with 2 hours (120 minutes), it returns 120 minutes as optimal session length
- This is correct mathematically, but conflicts with the configured 90-minute session length

**Fix Required:**
- Override session length for PE subjects to use configured baseSessionMinutes (90)
- Or add a constraint to force all sessions to be baseSessionMinutes regardless of duration_hours

### Issue 2: Teacher/Room Overlap Not Detected

**Root Cause:** The engine placed overlapping sessions for the same teacher in the same room

**Why This Happens:**
- The conflict detection (`isFree`) should have prevented this
- Possible bug in conflict detection logic
- Or the 2-hour sessions bypassed normal conflict checking

**Fix Required:**
- Investigate why conflict detection didn't prevent WI/PR1 overlap
- Ensure conflict detection works correctly for 2-hour sessions
